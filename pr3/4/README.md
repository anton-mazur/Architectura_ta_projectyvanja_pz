# Завдання 4. Діаграма станів (UML State Machine Diagram) — Сутність Booking

## 1. Обраний об'єкт
Для побудови діаграми станів обрано ключову бізнес-сутність: **`Booking` (Бронювання / Замовлення квитків)**.

Даний об'єкт має виражений динамічний життєвий цикл із чіткими бізнес-правилами переходу, критичними часовими обмеженнями (таймаут оплати 15 хвилин) та безпосереднім впливом на статус фізичних місць у залі (`FREE`, `RESERVED`, `SOLD`).

---

## 2. Опис станів сутності Booking (6 станів)

1. **`Created` (Створено / Ініційовано):**
   - *Значення стану:* Початковий стан замовлення після того, як користувач обрав місця на інтерактивній схемі залу. Сутність збережена в системі, але місця ще не закріплені в транзакції.
2. **`PendingPayment` (Очікує оплати):**
   - *Значення стану:* Місця успішно заблоковано в базі даних (переведено в статус `RESERVED`). Система активує 15-хвилинний таймер. У цьому стані замовлення очікує переказу коштів від клієнта через банківський еквайринг.
3. **`Confirmed` (Підтверджено / Оплачено):**
   - *Значення стану:* Банк успішно авторизував платіж і повернув код транзакції. Замовлення зафіксовано, місця в базі даних переходять у статус `SOLD`, а для клієнта згенеровано електронні квитки з унікальними QR-кодами.
4. **`Cancelled` (Скасовано):**
   - *Значення стану:* Замовлення анульовано або добровільно клієнтом, або внаслідок відхилення платежу банком (недостатньо коштів, помилка 3D-Secure). Всі пов'язані місця негайно розблоковуються і повертаються в статус `FREE`.
5. **`Expired` (Прострочено / Вичерпано ліміт часу):**
   - *Значення стану:* Клієнт не завершив оплату протягом відведених 15 хвилин. Спрацьовує системний таймаут, бронювання автоматично закривається, а заблоковані місця знову стають доступними для інших покупців.
6. **`Completed` (Завершено / Використано):**
   - *Значення стану:* Фінальний успішний стан замовлення. Настає, коли клієнт відвідав захід і пред'явив квиток контролеру (успішне QR-сканування на вході), або коли подія офіційно завершилася.
